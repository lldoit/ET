# KOF 包 (cn.etetet.kof) 设计文档

## 1. 架构方案
- **混合架构 (表现层驱动模拟，模型层权威状态)**: 
  逻辑帧、受击判定框(HitBox)探测以及动画时序均在 Unity 的表现层 (View) 中处理（类似于 UFE 使用 ScriptableObject 的方式），以此最大化编辑器的便利性和视觉反馈效果。
  然而，关键的角色状态（生命值、法力值/能量、异常状态等）以及最终的伤害计算，严格由 ET 模型层/热更逻辑层 (Model/Hotfix) 掌控绝对的权威。

## 2. 核心数据流向
1. **View -> Model**: Unity 表现层检测到碰撞发生（攻击框交汇在受击框上），向模型层发送一个包含攻击者 ID、防御者 ID 以及由于触发导致碰撞的招式 ID（或技能 ID）的事件（比如 `Evt_HitDetection`）。
2. **Model 处理**: ET Hotfix 层接收该事件，从只读配置（如 Excel/JSON）中查询该招式的权威伤害数值及碰撞属性，计算完抗性等公式后，真正扣除防御者的 HP （实体组件数值）。
3. **Model -> View**: ET Hotfix 层抛出一个状态变更/验证事件（如 `Evt_HPChanged` 或者 `Evt_StateTriggered` 击退）。
4. **View 响应**: Unity 表现层监听到 `Evt_HPChanged`，便随之更新 UI 界面上的血条，并在角色模型身上播放受击痉挛 (flinch/hit) 等相应的表现动画。

## 3. 网络与 MVP 开发范围
- **纯本地测试跑通 (Pure Local Play/Singleton)**: 最初的验证开发版 (MVP) 将专注在一个单机非网络环境下，建立核心的战斗循环闭环。玩家的全部按键输入、AI系统、前端视图逻辑、后端的权威模型计算流程全在本地发生。这将优先为“按键输入 -> 表现动画产生框体 -> 模型计算流转 -> 表现反馈动画”铺垫稳固地基，待其完善再去接入 ET 的状态同步体系。

## 4. 按键输入检测机制
- **表现层解析连招 (选项 A 方案)**: 
  Unity 的视图系统负责接收和缓冲原始物理输入指令（方向键、功能键），并负责维护按键的历史指令环形队列 (Command Buffer / Input History)。
  它将执行像是“正摇下前拳 (QCF+P) 释放波动拳”这样复杂的连招检测或正则匹配。一旦该特殊招式或者连击序列被识别，View 层会组发一条高优先级的带明确技能 ID 的 `Cmd_RequestSkill` 指令事件往后面的 ET 模型发去。
  - *设计缘由 (Rationale)*: 严肃的格斗游戏对于摇杆与按键的缓冲区窗口(Buffering)、组合输入等拥有极致的需求，并且对视觉上的帧停顿有着极度敏感的反馈关联。将此功能交由表现层能轻易调配例如 UFE 自带成熟缓冲机制并避开纯数据模型层对于海量冗余操作的空算耗度。模型层只需要做“该角色当下究竟有无释放指定 ID 技能的前提资格？”即可。

## 5. 解耦与事件交互
- **孤立的战斗逻辑**: 
  `cn.etetet.kof` 包将会深度利用 ET 既有的事件总线 (Event System) 来将特化的拳皇战斗链路与其他游戏底层（例如 `cn.etetet.bag` 物品栏逻辑，或 `cn.etetet.mmo` 常规逻辑）隔断。
  - 标准的一些诸如 `Unit` 或者 `C2M_SkillCmd` 等全局组件可通过扩展挂载 KOF 独有 Component，但 KOF 骨干战局业务（如 `KofBattleComponent`、`KofFighterComponent`）会在其内部处理几乎所有的 KOF 私有流转状态。
  - 当战斗环境（场景）开始或结束时，只依靠抛出极简的全局事件（如 `Evt_KofMatchStart`, `Evt_KofMatchEnd`）去通知局外原版系统接管工作进行转场（例如禁用平时用到的 `cn.etetet.move`，锁定角色的 Z 轴等等）。

## 6. 核心决策总结一览
1. **混合架构**: 表现层负责运行招式碰撞与表现；而模型层只看结果，紧握绝对计算判定。
2. **打击结算**: 前端碰出事件 -> 模型鉴定与算血 -> 模型全网广播 HP 变化 -> 前端去播放受击结果。
3. **MVP 范围**: 最初不碰联机，完全把单机一打一动作环节在 ET 中调优通过。
4. **搓招输入**: 搓招判定和缓存存放在 Unity 端，判定搓招成功后将成型技能结果交予模型。
5. **完全解耦**: KOF 自己挂载自己的核心 Component，以 Event 通知原有系统自身状态，各司其职。
