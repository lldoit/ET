# 增强百度批量翻译工具设计

## 方案

新增 Editor 侧工具类 `UII2LocalizationBaiduBatchTranslator`，负责批量翻译业务逻辑。`UII2LocalizationModule` 只保留 Odin 面板配置和按钮，避免继续膨胀。

工具提供三类入口：

- 语言码校验：只校验 I2 语言和百度语言码映射，不要求百度密钥。
- 待翻译预检：复用实际翻译的 Term 过滤逻辑，只统计预计请求数和字符数，不调用百度接口、不写入资产。
- 批量翻译：校验百度密钥后逐条请求百度接口，并写回 I2 Editor 语言源。

## 数据流

1. 从 `LocalizationManager.GetEditorAsset(true)` 读取 I2 Editor 语言源。
2. 根据源语言名和目标语言名查找 I2 语言索引。
3. 使用语言 `Code` 优先映射百度语言码，`Code` 为空时回退语言名。
4. 遍历 `mTerms`：
   - 只处理 `eTermType.Text`。
   - 默认只处理目标语言为空的条目。
   - 源语言为空、目标语言已有值、含 specialization 的条目跳过。
5. 使用现有 `GoogleTranslation.AddQuery` 复用 I2 的不可翻译标签保护逻辑，并用保护后的文本长度统计预计字符数。
6. 待翻译预检到此结束；批量翻译继续调用百度翻译接口，解析 `trans_result[0].dst`，还原不可翻译标签。
7. 批量翻译写回目标语言文本，并设置 `TranslationFlag.AutoTranslated`。

## 错误处理

- 缺少百度配置时，批量翻译直接提示；语言码校验和待翻译预检不要求密钥。
- 源语言或目标语言不存在时直接提示。
- 百度不支持语言码时直接提示。
- 单条翻译失败时记录失败数量并继续处理后续条目。
- 最终通过 Unity Console 和提示框输出统计摘要，提示框展示前 5 条失败明细，完整失败明细进入 Console。

## 边界

本次不做真实多行合并请求。百度接口支持多行 `q`，但项目文本本身可能包含换行和富文本标签，先采用逐条请求保证稳定性。后续若翻译量很大，再引入安全的 batch packer。
