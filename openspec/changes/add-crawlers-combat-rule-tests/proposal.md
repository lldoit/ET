# 增加 Crawlers 战斗规则可验证闭环

## 背景

`cn.etetet.crawlers` 已接入 UGF10，并已经具备战斗 Scene、手牌 UI、护盾显示、调试面板热键、战斗组件、牌堆、连段、卡牌效果、敌方前排行动、Boss 吟唱和状态刷新等基础能力。

当前风险在于 P0 战斗规则主要依赖手写 `CrawlerBattleSmokeSystem.RunSmoke` 和手动体验验证，尚未形成标准 `ATestHandler` 测试入口。后续继续扩展卡牌效果、敌人行为、回合队列和 UI 数据绑定前，需要先把已有规则核心转成可重复运行的自动化验证闭环。

## 目标

- 为 `cn.etetet.crawlers` 增加标准测试入口，覆盖 P0 战斗规则核心。
- 验证战斗可以从配置启动，并进入玩家回合。
- 验证玩家出牌会消耗灵力、移动手牌、结算伤害、护盾、抽牌和回蓝。
- 验证费用严格递增连段、Wild 补链和断链行为。
- 验证结束回合会结算剩余手牌、敌方前排攻击、护盾吸收和新回合抽牌。
- 验证 Boss 吟唱可按元素破势，并在未破势时按倒计时结算伤害。
- 验证胜利和失败结算状态。
- 通过 `dotnet build ET.sln` 和目标测试执行验证改动。

## 非目标

- 不调整 YIUI prefab、卡牌视觉、手牌动画或调试面板 UI。
- 不新增 Luban 表结构，不修改现有 Excel 配置来准备测试数据。
- 不扩展 `Defence`、`Poison`、`Summon`、`Disrupt` 等敌人行为。
- 不引入新的卡牌效果枚举或共享 schema。
- 不重构整个战斗系统；仅做测试暴露出的最小规则修补。
- 不做真实 Unity PlayMode 操作或完整人工战斗验收。

## 成功标准

- `Packages/cn.etetet.crawlers/Scripts/Hotfix/Test/` 下存在 `ATestHandler` 测试用例，类名前缀与 `PackageType.Crawlers` 对齐。
- 测试覆盖启动、出牌、连段、牌堆流转、敌方回合、Boss 破势和胜负结算。
- 如需测试辅助方法，落点遵循测试包规则，不污染运行时公共模型。
- 先观察新增测试失败，再实现最小代码让测试通过。
- `dotnet build ET.sln` 成功。
- 目标测试成功；若当前环境无法执行测试，明确说明阻塞点与已完成验证。

## 风险

- 当前规则读取正式配置，测试若直接依赖现有配置数据，未来配置调整可能影响断言稳定性。
- 若构造完全独立测试配置需要触碰配置 Singleton 或生成物，改动面可能扩大。
- `RunSmoke` 已覆盖部分路径，但断言粒度不足；迁移到标准测试时可能暴露现有规则边界问题。
- 测试运行入口依赖 ET.App Test 场景和本机运行环境，需要先通过构建确认基础可用。
